# 운영과 복구

## 실패 확인

Actions에서 실패한 실행의 단계와 로그를 확인합니다. 비밀 키와 API 응답 본문은 출력하지 않으므로 아래 순서로 점검합니다.

1. 테스트 실패: 코드·설정 변경을 확인하고 로컬 테스트를 실행합니다.
2. 수집·생성 실패: 출처 접근, Secret 이름, 모델 제공 여부, 무료 API 할당량을 확인합니다.
3. 커밋 실패: Actions 쓰기 권한과 브랜치 보호, 실행 중 원격 브랜치 변경 여부를 확인합니다.

모든 출처 실패, 차단·잘림·부정확한 구조의 AI 응답은 노트를 만들지 않습니다. 부분 출처 실패는 노트에 표시됩니다. 인증 오류는 자동 재시도하지 않으며 네트워크·429·일시적인 5xx만 총 3회까지 시도합니다. 실패 알림은 GitHub 개인 설정의 Actions 알림을 켜서 받으세요.

## 재실행

설정을 고친 후 기본 브랜치에서 수동 실행하거나 실패한 작업을 재실행합니다. 기존 날짜 노트는 자동으로 덮어쓰지 않습니다. 저장 실패 후 다시 실행하면 이전 일일 노트에 기록된 출처만 중복에서 제외하므로 미게시 뉴스가 유실되지 않습니다.

커밋 중 충돌은 강제 Push나 자동 병합으로 해결하지 않습니다. 최신 기본 브랜치에서 새 수동 실행을 시작합니다. 실패한 실행의 작업 파일은 GitHub에 게시되지 않았으므로 Gemini 요청이 다시 발생할 수 있습니다.

잘못된 일일 노트는 직접 편집하는 것이 기본 복구 방법입니다. 삭제 후 다시 생성하면 같은 날짜 노트가 새로 만들어질 수 있으며 API를 다시 호출합니다. 삭제는 사용자가 내용을 확인한 뒤 수행하세요.

## 새 소식이 없거나 특정 주제가 누락될 때

`status: no-news`는 수집에 성공한 출처의 최근 72시간 내 새 URL이 없다는 의미입니다. 실패한 출처까지 새 소식이 없다는 의미는 아닙니다. `config/sources.json`에서 출처를 변경할 수 있습니다. HTTPS, RSS 2.0·Atom 또는 GitHub Releases만 지원합니다. 날짜가 없거나 파싱할 수 없는 항목, 초안·프리릴리스는 제외됩니다. 자동 리디렉션을 허용하지 않으므로 출처의 최종 공식 URL을 등록하세요.

매일 최대 5개만 소개합니다. 소개하지 않은 항목은 다음 날 72시간 범위 안에 있으면 다시 후보가 됩니다. URL이 같은 문서의 본문 변경은 신규 뉴스로 취급하지 않습니다. Releases가 없는 프로젝트는 릴리스 출처에 넣어도 새 소식이 생기지 않을 수 있습니다.

## 예약 유지

Codex는 첨부 자산 메타데이터가 커서 최신 안정 릴리스 한 개만 조회합니다. 하루 사이 여러 안정 릴리스가 나오면 이전 버전이 생략될 수 있습니다. 다른 프로젝트는 최근 30개 릴리스를 조회합니다.

GitHub 예약 작업은 정시성을 보장하지 않습니다. 누락 시 수동 실행하세요. 공개 저장소가 60일간 활동하지 않으면 예약 작업이 비활성화될 수 있으므로 Actions 화면에서 상태를 확인하고 필요하면 다시 활성화합니다. 기준은 [GitHub 공식 문서](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)를 확인하세요.

자동화를 중단하려면 Actions에서 **AX 데일리 브리핑**을 비활성화합니다. 키를 폐기할 때는 Google AI Studio에서 폐기한 뒤 GitHub Secret도 정리합니다.

- 응답 검증 실패 원인은 한글을 포함하지 않은 본문 필드였다. 각 본문 필드의 한국어 문장 조건을 프롬프트에 명시하고 기존 검증은 유지했다.
- [실제 실행 및 재실행 기록](https://github.com/modac-bull/ax-knowledge-base/actions/runs/41002078077).

오류 로그는 허용 목록에 있는 안전한 원인과 HTTP 상태만 표시한다. API 오류 응답 본문과 알 수 없는 예외 메시지는 출력하지 않는다.
