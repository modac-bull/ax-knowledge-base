# AX 데일리 브리핑 설계

## 목적과 승인 범위

공개 뉴스와 개발 도구 업데이트를 수집하여 매일 한국 시간 오전 8시 전후에 한국어 브리핑을 생성한다. 사용자는 `modac-bull/ax-knowledge-base` 공개 저장소 신규 생성을 승인했다. 기존 개인 Obsidian Vault와 프로젝트의 `sources/` 파일은 사용하거나 변경하지 않는다.

## 결과물

- `00-Dashboard/Home.md`: 브리핑 및 학습 폴더 진입점.
- `01-Daily/YYYY-MM-DD.md`: 한국 날짜 기준 하루 한 개 브리핑.
- `02-Skills/`, `03-Topics/`, `04-Experiments/`: 공개 학습 메모 공간. 자동 생성기는 수정하지 않는다.
- `scripts/`, `tests/`, `config/sources.json`: 수집·검증·생성 코드, 테스트, 출처 설정.
- `.github/workflows/`: 비밀 키 없이 실행되는 검증과 예약·수동 생성 워크플로.
- `README.md`, `docs/SETUP.md`, `docs/OPERATIONS.md`, `SECURITY.md`: 한국어 설치·복구·보안 안내.

## 구현 선택 — 구현자 제안

Python 표준 라이브러리와 Gemini REST API를 사용하여 외부 패키지 설치를 최소화한다. RSS 2.0과 Atom, GitHub Releases API를 지원한다. 출처 기본값은 OpenAI 뉴스 RSS 및 `openai/codex`, `anthropics/claude-code`, `vercel/ai` 릴리스로 두고 설정 파일에서 변경한다. Matt Pocock Skills와 PStack은 Releases가 없는 경우를 고려해 학습용 참고 링크로 제공한다. 실제 수집 출처는 연결 상태를 검증하여 확정한다.

기본 모델은 무료 입력·출력이 공식 요금표에 제공되는 `gemini-2.5-flash-lite`로 제안한다. 실제 계정의 모델 제공 여부를 설정 시 확인하며, 저장소 변수 `GEMINI_MODEL`로 변경한다. 자동으로 다른 유료 모델로 전환하지 않는다. API 자체로 결제 상태를 보장할 수 없으므로 결제 미연결 무료 프로젝트를 사용한다. 무료 한도 초과 시 실패 처리한다.

## 실행과 생성 형식

예약은 UTC 23:00, 한국 시간 다음 날 08:00이다. GitHub 예약은 지연되거나 누락될 수 있으므로 정시 실행을 보장하지 않는다. 수동 실행도 제공한다. 최신 72시간의 공개 항목을 최대 30개까지 정리하여 Gemini에 전달하고 최대 5개의 주요 항목을 선택한다.

브리핑에는 발표 날짜·원문 링크, 핵심 요약, 중요성, 일반적인 웹 애플리케이션·TypeScript·패키지 빌드 도구 및 웹 애플리케이션 서비스 관점의 적용 제안, 10~20분 실험을 포함한다. 사실 요약과 적용 제안을 구분하고 본문이 없는 출처는 제목·메타데이터 기반임을 표시한다. 항목 수가 부족하면 있는 만큼만 작성한다.

모델에는 출처별 식별자가 포함된 공개 데이터만 전달한다. JSON 구조로 응답받아 스키마, 길이, 출처 식별자, 중복, 한국어 포함 여부와 종료 상태를 로컬에서 검증한다. 링크·제목·날짜는 모델 대신 검증된 원본 메타데이터에서 렌더링한다. 모델이 제공한 HTML·임의 링크·Obsidian 임베드를 그대로 저장하지 않는다. 수집 내용의 지시는 신뢰하지 않으며 실행하지 않는다.

## 중복 방지와 원자성

날짜 파일이 있으면 API 호출 전에 성공 종료하고 덮어쓰지 않는다. 이전 일일 노트에 저장한 정규화 URL 및 릴리스 식별자 해시로 이미 소개한 항목을 제외한다. 별도 공개 수집 원문이나 상태 파일 없이 노트 메타데이터를 중복 기록으로 사용한다. 쿼리 추적 매개변수·URL 프래그먼트를 제거한다.

신규 항목이 없고 출처 조회가 정상이라면 API 없이 `새로운 소식 없음` 상태 노트를 기록한다. 모든 출처가 실패하면 노트를 만들지 않고 실패한다. 일부 출처 실패는 노트에 수집 범위를 표시한다. 생성 실패 시 노트를 만들지 않으며 재실행으로 복구한다. 검증 후 임시 파일을 최종 경로로 원자적으로 옮긴다.

## 보안과 운영

`GEMINI_API_KEY`는 GitHub Actions Secret에만 등록한다. `.env*`, `.obsidian/`, `.trash/`, 로컬 로그와 캐시는 Git에서 제외한다. 무료 Gemini에는 공개 정보만 전달하며 키·환경변수·회사 자료를 프롬프트나 로그에 포함하지 않는다.

설정된 HTTPS 출처만 요청한다. 응답 크기와 시간을 제한하고 임의 URL 및 내부 네트워크로의 리디렉션을 막는다. 출처 텍스트는 길이를 제한하고 HTML을 제거한다. 일시적 HTTP 오류에는 최대 3회, 제한된 지수 백오프를 적용한다. 인증·응답 형식 오류는 재시도하지 않는다. API 오류 본문과 비밀 값은 로그에 출력하지 않는다.

예약·수동 생성은 기본 브랜치에서만 허용하고 동시 실행을 직렬화한다. Actions 의존성은 검증한 커밋 해시로 고정한다. 테스트 작업은 읽기 권한만 가지며 API 키를 전달받지 않는다. 생성 작업만 `contents: write`를 사용한다. 자동 커밋은 해당 날짜의 `01-Daily/` 파일만 명시적으로 추가한다. 충돌 시 강제 푸시하지 않고 실패한다. 프로젝트 소스나 전체 작업 디렉터리를 일괄 추가하지 않는다.

실패 알림은 GitHub Actions 기본 알림을 사용한다. 별도 이메일·Slack 발송은 구성하지 않는다. 60일간 저장소 활동이 없으면 공개 저장소의 예약 작업이 비활성화될 수 있음을 운영 가이드에 설명한다.

## 검증 기준

고정된 RSS·Atom·릴리스 및 Gemini 응답을 이용한 네트워크 없는 테스트로 파싱, 시간대 경계, URL 정규화, 날짜·기사 중복, 일부/전체 수집 실패, 모델 응답 오류, 출처 위조, 타임아웃, 재시도, 비밀 값 미출력과 실패 시 파일 미생성을 확인한다. 실제 출처 수집도 별도 확인한다. Gemini 키 등록 후 수동 Actions 실행으로 실제 노트 생성과 재실행 무변경을 검증한다. 키가 없으면 실제 생성 검증을 완료했다고 보고하지 않는다.

## 사용자 설정과 남은 외부 단계

현재 GitHub 연결 계정은 `modac-bull`이다. 대상 저장소 조회는 404였고 연결된 저장소 검색 결과도 비어 있었다. 로컬 `gh` 인증은 유효하지 않으며 브라우저 접근은 시간 초과되었다. 저장소 생성이 불가능한 동안 로컬에서 구현 및 검증을 준비하고, 인증이 복구되면 승인된 공개 저장소를 생성하고 코드를 게시한다.

사용자는 공식 `gh auth login --hostname github.com --web`으로 인증을 복구하거나 GitHub 웹에서 공개 저장소를 생성하고 연결 앱에 접근 권한을 부여한다. API 키는 채팅에 보내지 않고 저장소 Settings → Secrets and variables → Actions에 등록한다.

Obsidian은 사용자가 별도 폴더에 이 저장소를 복제하고 `Open folder as vault`로 연다. Git Pull로 확인한 뒤 공식 커뮤니티 플러그인 목록의 Obsidian Git을 통해 시작 시 및 주기적 Pull을 설정한다. 기본 안내는 자동 Push를 끄고 로컬 메모 변경을 수동 커밋하는 방식이다. 개인 Vault·회사 저장소와 합치지 않는다. 기기가 꺼져 있으면 다음 실행 때 동기화된다.

## 완료의 정의

구현·오프라인 테스트·설정 가이드 제공, 원격 저장소 게시, Secret 등록 뒤 실제 Actions 성공과 날짜 중복 방지 확인, 별도 Vault 연결 안내까지 마친다. 인증 또는 API 키 미등록으로 수행하지 못한 단계는 남은 작업으로 명확히 보고한다.
